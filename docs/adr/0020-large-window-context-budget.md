# 0020. 为当前大窗口模型提高默认输入预算

- 状态：Accepted
- 日期：2026-10-19
- 来源：工作区未提交变更；提交时补实际 commit hash 与 subject

## 背景

[0019](0019-default-context-budget.md) 以容纳大页工具输出为目标设置默认输入预算。
准备运行真实仓库评测时，用户明确要求先提高预算，避免在当前默认模型仍有大量窗口
空间时过早压缩定位、修改和验证历史。

当前使用的 `deepseek-flash` 对应 DeepSeek V4.1 Flash，
[官方文档](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/) 标明 1M 上下文窗口。
此前的默认触发点远低于该容量。现有评测不足以量化提前压缩造成的成功率损失，
本次调整是面向当前模型的容量选择，不是已验证的性能优化。

## 决策

- 提高默认估算输入预算，为当前大窗口模型延后压缩，并为估算误差及输出保留空间。
  当前数值与派生阈值统一见 README「上下文与会话存档」。
- 保留估算与校准方式、触发和压缩后目标比例、近期保留比例、摘要长度比例，以及
  工具交互完整性、失败不提交、先持久化后更新内存的规则。
- 使用现有配置覆盖入口，不新增模型窗口探测、tokenizer、依赖或配置项。当前默认
  不适用于所有模型；较小窗口须显式降低预算。
- 压缩压力测试继续显式设置小预算；历史评测的显式配置不随新默认值改变。

## 备选方案与取舍

| 备选 | 为什么不采用 |
| --- | --- |
| 保留原默认值，只在每次评测时覆盖 | 当前主要使用大窗口模型，真实任务和新 workspace 均需要更合适的默认容量 |
| 根据模型窗口动态计算压缩阈值 | 需要引入模型能力来源、输出预留和覆盖规则，超出本次仅调参的范围 |
| 直接把预算设为模型完整窗口 | 估算并非精确计数，摘要输入也使用该预算，需保留输出及估算误差余量 |

## 后果

压缩会延后，可能保留更多原始执行细节；较长上下文也可能增加延迟和费用，不保证
任务成功率提升。近期原文预算和摘要长度上限会随同一个参数一起扩大，暂不解耦。
摘要长度上限不是实际输出长度，也不会自动改变 Provider 的输出限制。

**重新评估的触发条件**：切换窗口明显不同的模型；观察到上下文超限、冗长摘要或
不可接受的延迟与费用；或者需要独立控制触发点、近期保留量及摘要长度。
