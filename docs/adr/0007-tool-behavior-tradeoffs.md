# 0007. 工具行为取舍：read 分页、edit 唯一精确匹配、检索依赖 ripgrep

- 状态：Accepted
- 日期：2026-09-23
- 来源：`70af0ec` 可续读文件、检索与会话错误恢复；`ce3f600` bash 单次工作目录与 edit 错误诊断

## 背景

对模型可用的工具共六个（`read`、`write`、`edit`、`bash`、`glob`、`grep`）。它们的接口设计直接决定了模型能不能自我纠错：报错信息太笼统，模型只能反复重试同样的调用；一次读取整份文件，会瞬间吃掉上下文预算（见 [0009](0009-estimated-context-compaction.md)）。

具体遇到的问题是：`edit` 的失败没有可操作信息；大文件一次读完不可行；检索没有工具就只能靠模型自己拼 `bash` 命令。

## 决策

### `read` 按行分页并可续读

- `read(path, offset=1, limit=200)`，`offset` 从 1 开始，`limit` 上限 500。
- 输出附行号；单行只展示前 2 KiB 并标注不完整；每次输出至多 40 KiB。
- 有后续行时返回 `next_offset`，用相同路径即可继续读取。
- **不统计剩余总行数**——需要额外遍历整个文件，代价与收益不符。
- 文件不存在、是目录、二进制内容、无效 UTF-8 分别返回**可区分**的错误，让模型知道该换路径还是换文件。

### `edit` 要求唯一精确匹配

- 只替换**唯一**的精确匹配；`old_text` 与 `new_text` 相同时报错（`new_text` 允许为空串，删除是合法操作）。
- 找不到文本：报错并附 `old_text` 首行预览，提示改用 `read` 或 `grep` 定位。
- 多处匹配：**不写文件**，列出最多 5 个 1-based 行列位置及短上下文，提示用更长的 `old_text` 精确到一处。
- 匹配按**不重叠**方式枚举。
- 失败路径一律不修改文件。

### 检索依赖外部 ripgrep

- `glob(pattern, path=".", limit=100)` 查找文件；`grep(pattern, path=".", glob=None, limit=100)` 做区分大小写的逐行正则搜索，返回 `路径:行号:预览`。
- 直接调用系统 `rg`，**遵循 ripgrep 默认的忽略规则**（`.gitignore`、隐藏文件、二进制文件、符号链接）；显式 `glob` 可能覆盖部分忽略规则。
- 两者最多返回 200 条、40 KiB，搜索 15 秒超时。
- 启动时若找不到 `rg` 则**明确报错**，不静默降级。

## 备选方案与取舍

| 备选 | 为什么不采用 |
| --- | --- |
| `edit` 支持模糊 / 正则替换 | 模糊替换在代码上容易改错位置，且失败模式难以让模型理解；精确匹配的失败是可解释的 |
| `edit` 多处匹配时替换第一处 | 静默选择一处是最危险的失败模式——模型会以为改动已生效 |
| `read` 一次返回整个文件 | 大文件会直接撑爆上下文预算；分页把「读多少」的决定权交给模型 |
| `read` 返回剩余总行数 | 需要完整扫描文件，与分页省成本的初衷相悖 |
| 用纯 Python 实现文件遍历和正则搜索 | 无法获得 ripgrep 的忽略规则、并行扫描和二进制文件处理；自研版本要么更慢要么更不兼容 |
| 找不到 `rg` 时降级到纯 Python 实现 | 两套搜索语义会长期漂移，且用户无法察觉自己拿到的是哪一套 |

## 后果

- 代价：引入了一个**非 Python 的硬运行时依赖** `rg`。这是项目里唯一的此类依赖，安装说明中必须强调（`README.md` 的 Quick Start）。
- 代价：检索行为绑定 ripgrep 的语义，包括它的忽略规则——这通常符合预期，但「为什么这个文件搜不到」需要用户理解 ripgrep 的规则。
- 代价：`grep` 只做区分大小写的逐行正则，不支持多行匹配、上下文行数等高级用法。超限时需要用户或模型缩小路径或模式。
- 收益：错误信息可操作，模型能据此自我纠正，而不是盲目重试。

**重新评估的触发条件**：若需要跨平台分发且不能要求用户安装 `rg`，应考虑内置搜索实现并把两套语义统一——那将是一篇取代本 ADR 的新决策。
