# 0019. 默认输入预算兼容合法的大页工具输出

- 状态：Accepted
- 日期：2026-10-18
- 来源：工作区未提交变更；提交时补实际 commit hash 与 subject

## 背景

[0009](0009-estimated-context-compaction.md) 将默认估算输入预算设为 32768，压缩后的
完整请求必须不超过预算的一半。`read`、检索及 Shell 的合法输出可以接近 40 KiB；
仅一个大页与当前必须保留的工具交互，就可能超过 16384 的目标，导致有旧历史可压缩
时仍抛出 `ContextError`。

本地探针使用真实 `read` 生成 40099 字节输出，连同默认六个工具定义、简短 system
与当前用户输入估算为 17384 token。新增回归在旧默认预算下复现这一失败；它只使用
本地假 Provider，不依赖真实模型调用。

主流方案也把模型容量、触发点和近期保留量分别考虑：

- [Codex 配置参考](https://developers.openai.com/codex/config-reference/) 的自动压缩阈值
  默认依模型确定，可单独覆盖。
- [Claude Code](https://code.claude.com/docs/en/how-claude-code-works) 在接近上下文上限时
  自动管理历史，压缩仍可能丢失细节。
- [OpenCode V2](https://dev.opencode.ai/v2/docs/compaction/) 默认保留约 15000 token 的
  近期对话，并按模型窗口预留缓冲。

这些产品的模型窗口与本项目的估算输入预算语义不同，不能直接照搬触发百分比。
Codehead 用于学习 Harness，仍需要明确、较小的预算与可单独降低预算的压缩实验。

## 决策

- 默认输入预算提高为 65536，覆盖合法单次大页输出所需的近期保留空间；不按模型
  标称最大窗口自动扩张。显式配置继续覆盖默认值，下限不变。
- 保留 0009 的估算公式、仅向上校准、75% 触发、50% 目标、约 25% 近期保留量和
  1/16 摘要上限；system 与最新用户输入仍固定保留，完整工具交互不拆分。
- 保留 0009 的摘要语义、分批合并、失败不提交及先持久化后更新内存的事务边界。
  不引入 tokenizer、模型能力注册表、自动重试或新的配置项。
- 压缩压力测试继续显式使用较小预算；已有评测中的 32768、16384 等配置保持原样。

## 备选方案与取舍

| 备选 | 为什么不采用 |
| --- | --- |
| 保持 32768，只提高触发比例 | 不改变 16384 的压缩后目标，无法解决完整工具交互放不下的问题 |
| 保持预算，缩小工具输出或丢弃最新结果 | 改变现有工具反馈与交互完整性，超出本次默认配置调整范围 |
| 同时提高压缩后目标比例 | 改变压缩策略并缩小下一次压缩前的增长空间，没有当前证据支持 |
| 直接使用模型最大窗口 | 模型绑定与运行成本增加，也不利于低成本观察压缩机制 |

## 后果与重新评估条件

活跃原文和摘要可保留更多内容，压缩会更晚触发；长会话单次输入与摘要的潜在开销
也会增加，不能把更少的摘要请求直接等同于更低总成本。本次只验证容量边界，不声称
真实模型成功率或 token 成本改善。

默认预算仍不保证容纳任意 system prompt、校准系数或多工具大输出组；这些情况继续
遵循现有明确失败语义。若真实仓库任务持续因预算失败，或需要支持窗口更小的模型，
再以记录的输入体量与失败原因调整预算或保留策略。

本决策取代 0009 的默认预算结论，其余压缩机制按上文保留；0009 正文保持不变。
