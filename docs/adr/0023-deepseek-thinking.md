# 0023. DeepSeek 思考内容随消息保存，摘要单独关闭思考

- 状态：Accepted
- 日期：2026-10-20
- 来源：基于 `e916944` 的工作区变更

## 背景

[0016](0016-runtime-configuration.md) 定义了启动配置快照，provider 此前固定关闭
DeepSeek 思考模式，并丢弃思考响应。根据 [DeepSeek 当前协议](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode/)，
携带工具的后续请求必须回传历史思考内容。因此开放开关同时需要扩展
[0002](0002-unified-domain-models.md) 的消息契约和 [0010](0010-resume-contract.md)
的恢复校验；只改请求参数会留下无法续聊的历史。

## 决策

- 沿用现有 provider，在构造时固定思考开关与强度，显式发送开关。当前只适配 DeepSeek，
  不新增厂商选择框架或任意参数透传接口。
- 思考内容是 assistant 消息的可选字段，缺失与空字符串区分，完整响应通过原有
  “校验后提交”边界保存。思考增量不冒充正文，也不新增展示事件。
- 携带工具时，已有思考字段独立于当前模式回传；开启模式要求活跃历史和成功新响应
  都有该字段。失败、截断、取消仍沿用原有拒绝和提交语义，不补造思考内容。
- 恢复时在认领事务内检查活跃消息，拒绝时回滚；provider 的发送前检查作为最终防线。
  检查不重新加载已压缩原文，也不重新执行工具。
- 思考内容随消息 JSON 存档并计入上下文预算。压缩以原消息和工具交互组为单位，
  保留消息的思考字段不变。摘要仅使用正文和工具记录，通过请求级覆盖明确关闭思考，
  以控制摘要延迟与输出预算；这不改变启动配置，也不修改 provider 的共享状态。
- SWE-bench 显式传递相同设置，保留原有输出及费用约束；输出上限覆盖思考与正文合计。
  配置与驱动指纹变化后重新完成相应验证。报告展示新设置，并仅对已核实的旧驱动指纹
  标注实际关闭；旧配置里的 `disable_thinking=false` 不能证明旧 worker 开启过思考。

## 备选方案与取舍

| 备选 | 为什么不采用 |
| --- | --- |
| 仅开放请求开关，在 provider 内缓存思考 | 缓存会与压缩、恢复后的活跃消息脱节，丢失可重建的请求状态 |
| 关闭模式就删除历史思考字段 | 历史回传义务取决于工具协议，不能由当前生成开关推断 |
| 缺失思考时补空字符串或自动降级 | 掩盖旧历史和响应缺失，无法证明与服务端语义一致 |
| 恢复成功后再检查 | 认领已提交，失败可能使正常关闭的会话遗留为 active |
| 摘要沿用思考模式 | 目前摘要目标简单，新增思考没有已验证收益，且会消耗同一输出预算 |
| 开启思考就自动放宽评测预算 | 会改变费用预留和基线可比性，应以显式预算和试点数据调整 |

## 后果

- 新代码可读取缺失字段的旧消息，开启思考时可能拒绝旧会话；关闭思考或新建会话即可。
  新消息 JSON 包含可空字段，旧代码的严格字段校验可能无法读取，降级格式兼容不保证。
- 回传历史思考会增加上下文占用，即使当前关闭；长思考仍可能触发既有压缩边界错误。
- 摘要请求级覆盖扩大了请求契约，但保持单条流式路径和计费包装，避免另建摘要客户端。
- 强度与输出上限无法保证不截断；真实模型下的截断率、压缩频率、延迟和费用需单独试点。
  离线测试不能证明所有混合历史均被真实 API 接受。

**重新评估的触发条件**：出现第二家模型协议、必须展示思考增量、需要无损迁移旧思考历史，
或试点证明当前摘要与输出预算策略不能满足实际任务时，再扩展相应边界。
