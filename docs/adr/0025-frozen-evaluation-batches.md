# 0025. 固定评测批次与实际执行身份门禁

- 状态：Accepted
- 日期：2026-10-20
- 来源：工作区变更

## 背景

[0021](0021-swebench-evaluation-boundary.md) 的首轮固定三题已完成。
扩题需要保留调试集与历史证据，且仅检查评测脚本指纹不能证明安装进镜像的核心源码
已包含 Shell 修复。直接从仓库名推断包名也不能覆盖 sklearn 和 src/lib 布局。

## 决策

- 以显式 `--config` 选择冻结批次；宿主保存不可被不同配置覆盖的快照，可信控制端
  读取同一文件。原三题和新批次使用独立产物根目录，不重置 attempt，不自动重试。
- 核心按实际可导入包的 Python 源码计算指纹，规范 CRLF/LF；评测驱动也规范换行。
  宿主、已安装核心、离线验收、控制镜像与逐题推理镜像身份共同约束付费运行。
  每个推理镜像直接执行项目导入及真实 Shell 回归；重建时使用首轮依赖约束，避免
  将升级依赖混入 Shell 实验。
- 原三题重跑保持 40 步、含摘要 50 次请求。新 20 题使用 100 步、含摘要 125 次请求，
  沿用其他模型、工具、时间参数；两组各自按累计 40 元停止、50 元保守预留上限控制。
- 新批次排除三题，给全部仓库各一题，剩余名额按剩余容量最大余数法分配，余数同分
  按仓库名排序。仓库内按固定种子与实例 ID 的 SHA-256 排序取题，仓库间轮转运行。
  清单与顺序在付费前冻结，失败与环境阻塞均不换题。
- 对支持仓库显式记录导入名、源码包路径及安装元数据路径；仅保留原有允许的运行
  二进制、翻译文件、包根版本文件和必要安装元数据，不放宽为复制所有忽略文件。

## 备选与代价

直接改原三题配置会模糊历史身份；根据结果换题会引入选择偏差；复用脚本指纹但不
核验核心镜像可能在旧工具上付费。全部门禁先行增加免费准备与评分时间，覆盖小仓库
也使样本不再按题量比例代表 Lite 总体。三题历史环境不同，前后结果仅用于诊断，
不能单独归因于 Shell 修复；正常收尾与官方 resolved 分别报告。

本次不更改完成条件，不增加修改范围限制，也不引入并发推理或重试。
重新评估条件：完整固定批次显示新的可重复失败，或评测规模要求独立设计资源调度。
