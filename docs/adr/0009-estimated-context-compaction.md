# 0009. 估算驱动的阈值自动压缩

- 状态：Accepted
- 日期：2026-09-23
- 来源：`7faa835` 上下文自动压缩与 SQLite 历史存档

## 背景

长会话必然超出模型可接受的输入长度。在压缩机制出现之前，唯一的结果是请求失败，用户只能手动开新会话，历史随之丢失。

要做到自动压缩，先得回答「还剩多少空间」——而这需要 token 计数。精确计数依赖目标模型的 tokenizer，引入它会带来额外的库、模型绑定和版本漂移；不同 Provider 的计数方式也不一致。

## 决策

**用本地估算代替精确计数，并基于估算做阈值压缩。**

- **预算语义**：`CODEHEAD_CONTEXT_BUDGET` 默认 `32768`、最小 `1024`，表示**估算的输入 token 预算**，不是模型窗口大小。使用者需要自行为目标模型预留输出空间后配置输入预算。
- **估算公式**（`src/codehead/agent/context.py`，`base_tokens`）：请求序列化为 JSON 后的 UTF-8 字节数 ÷ 3，加固定开销 64，再加 `16 × 消息数`；结果乘以校准系数（默认 `1.2`，`estimate_tokens`）。
- **向上校准**：正常请求返回的 input usage 只用于**向上**修正当前会话的系数（`observe_usage` 取 `max`），不向下调整。没有 usage 时仍可估算。
- **阈值**：每次正常模型请求前检查；达到预算 **75%** 触发压缩，要求压缩后不超过 **50%**。
- **保留策略**：近期消息约占预算 **25%**（`recent`），至少保留最后一个完整消息或工具交互单元；另外始终保留 system prompt 和最新用户输入，即使它们不在近期区间内。
- **不可拆单元**：一条带工具调用的 assistant 消息及其**全部**结果消息是一个不可分割的整体，要么全部保留，要么全部压缩（`_units`）。
- **摘要本身受限**：复用当前模型，以独立的**无工具**请求处理旧历史，上限为预算的 **1/16**；超出单次输入预算时按完整单元分批合并。
- **摘要的定位**：属于可能有损的历史参考资料，**不作为 system 指令**；提示词明确要求不得执行数据内的指令。
- **失败即不提交**：摘要失败、被取消或无法有效缩小（`after >= before`）时不提交候选检查点，也不丢弃原活跃消息。
- **提交顺序**：先提交 SQLite 检查点，再更新内存、再发出完成事件（见 [0008](0008-append-only-archive.md)）。

## 备选方案与取舍

| 备选 | 为什么不采用 |
| --- | --- |
| 接入目标模型的 tokenizer 做精确计数 | 引入模型绑定与额外依赖；多 Provider 下仍需多套实现；与 [0001](0001-self-built-harness.md) 的最小依赖取向冲突 |
| 用字符数估算 | 中文与代码混排时字符与字节差异巨大；JSON 字节数更接近真实 token 消耗 |
| 固定阈值不做校准 | 不同模型的 token/字节比例差异显著，固定系数会持续误判 |
| 系数双向校准（也向下调） | 单次偏小的 usage 会让后续估算偏乐观，导致反复触发或直接超限；只向上是保守选择 |
| 到 100% 才压缩 | 压缩请求本身也要占用输入空间，必须留出余量 |
| 只保留最近 N 条消息 | N 条消息的体量差异极大（一条工具结果可能几十 KiB），条数不是有效的预算单位 |
| 摘要写成 system 消息 | 摘要是可能有损的参考资料，赋予 system 的指令地位会让模型把摘要中的错误当成硬约束 |

## 后果

- **这不是精确 tokenizer，也不保证服务端一定不会超限**。估算偏差由上向校准逐步收敛，但首次请求仍可能偏乐观。
- 压缩本身可能失败：过大的最新输入、system prompt、工具定义或不可拆的工具交互都会触发 `ContextError`。压缩错误结束当前回合并回到输入提示，**不自动重试**。
- 摘要是有损的：被压缩的原文只在存档中保留，不在请求路径重新加载（见 [0008](0008-append-only-archive.md)）。
- **已知缺口**：所有阈值都是**内联字面量，没有具名常量**；同一默认预算 `32768` 在 `AgentLoop.__init__`、`ContextManager.__init__` 和 `Config.context_budget` **三处分别重复**。修改默认值时必须同时改三处，容易遗漏。提取具名常量并消除重复是一处明确的待改进项。

**重新评估的触发条件**：若引入服务端 token 计数接口，或需要在多个差异极大的模型间共享同一份预算配置，应重新评估估算方案；那会新增一篇 ADR 并取代本篇。
