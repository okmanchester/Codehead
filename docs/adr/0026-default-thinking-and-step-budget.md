# 0026. 默认开启思考并统一为 100 步

- 状态：Accepted
- 日期：2026-10-20
- 来源：工作区变更

## 背景

[0023](0023-deepseek-thinking.md) 已支持思考模式及摘要单独关闭思考，
[0025](0025-frozen-evaluation-batches.md) 已区分历史实验和冻结批次。
Astropy 非思考复验分别耗尽 40、100 步，开启思考的一次复验在 18 次请求后完成。
单题单次结果不能证明稳定收益；用户决定统一后续默认配置，保留更大的处理余量。

## 决策

- RuntimeConfig、直接构造的 OpenAIProvider 和默认评测配置均默认启用思考，强度 high。
- AgentLoop 与主程序每回合默认最多 100 次正常模型请求；默认评测及尚未运行的
  20 题配置最多 100 次正常请求、含摘要共 125 次请求。步数耗尽仍记为失败。
- 摘要请求继续显式关闭思考；配置来源优先级、显式关闭开关、上下文、输出及时间、
  费用上限沿用现有规则。100 步不保证都能执行，其他上限可先触发。
- 已运行实验的专用配置与产物快照不改写。20 题清单和顺序保留，思考开关更新后须
  使用新产物目录，源码与配置变更使旧验收失效，重新构建和验收后才能付费运行。

## 备选与代价

保留非思考默认值、仅增加步数不能解决已观察到的重复排查；仅开启思考而保留较小
步数不符合本次统一预算的要求。统一默认值可能增加延迟和单回合费用，且不能保证
消除循环。旧会话缺少 reasoning_content 时，继续按现有契约拒绝思考模式恢复，
用户可显式关闭思考或新建会话。

重新评估条件：固定批次出现可重复的截断、成本或完成率退化，或更换模型后协议与
预算假设失效。
