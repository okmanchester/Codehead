# 0016. 运行时配置值对象与项目 TOML 加载边界

- 状态：Accepted
- 日期：2026-09-28
- 来源：工作区未提交变更（提交时补实际 commit hash 与 subject）

## 背景

现有 `Config` 和 `LocalConfig` 把环境读取与配置值混在一起，CLI 的回合步数仍来自
AgentLoop 默认参数。配置来源增加到文件后，需要将来源合并、路径解析和运行参数校验
明确放在启动边界。

[0009](0009-estimated-context-compaction.md) 已指出输入预算默认值重复定义的问题；
[0010](0010-resume-contract.md) 要求恢复使用当前配置，且会话列表不需要完整模型环境。
本决策补充这些约束，不改变预算或恢复语义。

## 决策

- `config.py` 只定义不可变的 `LocalConfig`、`RuntimeConfig` 和共享默认值；
  `config_loader.py` 负责环境、TOML、来源合并以及 workspace 解析。旧 `Config` 名称
  和 `from_env()` 入口直接迁移，不增加兼容包装。核心模块不读取配置来源。
- 沿用现有 `.env` 加载方式，以环境变量或当前目录选定 workspace，再读取其中单个
  `.codehead/config.toml`。文件采用平铺字段；workspace 和凭据由环境提供，避免文件
  反过来改变自身发现位置。使用标准库 `tomllib`，不增加依赖。
- 默认值由文件覆盖，再由环境覆盖；进程环境优先于 `.env`，空环境变量不参与覆盖。
  完整加载器在合并后校验运行参数，包括严格整数类型和下限。未知字段和文件读取、
  解析错误明确报告；缺失文件使用默认值。
- CLI 在启动时加载一次，并将参数传入现有组件构造函数。配置是当前进程的快照，
  无全局可变配置和热重载；恢复使用此快照，不从历史存档恢复运行参数。
- 本地加载器只验证路径值，不要求凭据或有效的模型参数，供 `--list-sessions` 使用。
  文件语法和未知字段检查仍然生效。权限文件继续独立管理，不纳入本次配置合并。

## 备选方案与取舍

| 备选 | 为什么不采用 |
| --- | --- |
| 继续把所有加载逻辑放在值对象的类方法中 | 来源合并与运行时值耦合，难以明确构造对象是否读取环境 |
| 文件优先于环境 | 会改变已有启动脚本和临时环境覆盖的使用方式 |
| 用户级、项目级、命令行多层配置 | 当前需求只有项目配置，提前增加发现和优先级规则会扩大初版边界 |
| 引入配置框架或全局单例 | 标准库和已有 Pydantic 足够，全局状态也不利于嵌入调用和测试 |

## 后果

- 嵌入调用方须迁移到新名称和加载函数；直接构造值对象仍可用于显式注入。
- `.env` 中的旧运行参数会继续覆盖 TOML，因此示例仅启用密钥，其余变量作为可选
  注释提供。单个项目文件不可用于跨项目共享配置，也不能配置 workspace 或密钥。

**重新评估的触发条件**：出现跨项目共享配置、多模型 profiles 或运行中切换参数的
明确需求时，再扩展配置层次和生命周期。

## 代码与测试

- `src/codehead/config.py`、`config_loader.py` — 值对象、来源加载、合并与校验
- `src/codehead/cli.py` — 启动快照和组件参数传递
- `tests/test_config.py`、`test_cli.py`、`test_resume_cli.py` — 优先级、非法输入、步数及列表和恢复边界
