# Codehead 小任务集

这是一组原创、可手工初始化的 Python 小仓库任务，用于观察 Codehead 在真实模型调用下的行为。任务代码、输入和预期结果均在 Markdown 中给出；运行记录仅在本地保留，单轮结果不代表稳定的难度或步数需求。

001～010 不依赖网络服务、第三方 Python 包或大型项目；011～013 使用 Codehead
真实仓库及其现有开发依赖。它们是早期诊断样本，不代表完整的编码能力基准，也不适合用少量结果对模型排名。

## 文件保留与版本管理

| 类别 | 内容 | 处理方式 |
| --- | --- | --- |
| 需要跟踪 | 本说明和可复用任务规范 | 放在本目录；不逐轮提交运行快照 |
| 本地保留，不跟踪 | 每轮的 `REPORT.md`、精简 `results.json` | 放在 `docs/evaluation/runs/<运行编号>/`，由 `.gitignore` 排除；指标保留配置、逐题统计、验收结论和关键发现 |
| 本地保留，不跟踪 | 原始事件、会话数据库、最终产物、标准流、详细验收记录、原始配置与代码差异、本次专用脚本 | 压缩到仓库根目录 `.codehead/evaluations/<运行编号>.zip`；`.gitignore` 已忽略 `.codehead/` |
| 直接删除 | 可重建的初始副本、验收/变体运行副本、初始化与提示词副本、派生审计文件、过期验收日志、缓存和临时 workspace | 提取关键结论并校验归档后删除 |

本地运行记录和归档不随 Git 克隆分发，需要排查原始记录时再解压。运行专用脚本不作为稳定评测框架维护。
早期五轮运行快照已从当前版本移除，可从 Git 历史查询；对应的本地 ZIP 归档继续保留。

## 如何初始化

1. 每次使用一个全新的独立目录作为任务 workspace，放在 Codehead 仓库之外。只创建任务文档中「初始文件」列出的文件，以及下方公共 `AGENTS.md`。标注为初始化脚本的代码仅由评测者执行。
2. 文件默认使用 UTF-8、LF；008 会单独指定 CRLF。没有写出的空目录不用创建。所有任务使用 Python 3.12 或更高版本。
3. `tests/` 是公开测试，初始化时放进 workspace；「评测者验收」及其额外用例不放进去。不要把整个任务 Markdown 复制到 workspace，也不要把其全文作为 prompt。
4. 给 Codehead 的输入只取「给 Agent 的提示词」。初始代码中的缺陷是任务的一部分，不要预先修复。
5. 在 Agent 执行前保存初始文件副本或 Git 基线。每次重复评测重新初始化，不能沿用上一次修复的目录或会话。

公共 `AGENTS.md`：

```markdown
# 项目约束

- 默认使用中文回答。
- 使用 Python 标准库，不增加第三方依赖。
- 只修改当前任务要求的文件；不要修改或删除已有测试来规避问题。
- 可以增加测试。测试使用 unittest，从 workspace 根目录执行：
  python -m unittest discover -s tests -v
- 不修改 AGENTS.md。最终说明修改了什么、验证了什么；未运行的检查明确写出。
```

007 的任务范围是新增测试，001 是只读分析，以各题提示词为准。010 第一回合要求等待，也不应立即修改代码。

## 如何交给 Codehead

001～008 的提示词分别保存到 workspace 之外的 UTF-8 `prompt.txt`。在终端中明确把 `CODEHEAD_WORKSPACE` 指向该任务的绝对目录，并确认模型、端点、输入预算及步数配置。原仓库的 `.codehead/config.toml` 不会自动成为新 workspace 的项目配置。

这些题需要允许 Agent 编辑和执行命令，可在准备好的一次性执行环境中使用：

```text
codehead -p --allow-all-tools < prompt.txt
```

上面是支持 stdin 重定向的 shell 表示法；PowerShell 不支持同样的 `<` 写法。PowerShell 7 可使用：

```powershell
$OutputEncoding = [System.Text.UTF8Encoding]::new($false)
Get-Content -LiteralPath $promptFile -Raw -Encoding utf8 | codehead -p --allow-all-tools
```

`$promptFile` 由评测者设置为任务提示词文件的绝对路径。001 也可以不加 `--allow-all-tools`，但应记录实际权限设置，避免把不同配置的重复运行合并比较。

009 必须按该题的权限文件运行，**不能使用 `--allow-all-tools`**，否则会覆盖拒绝规则。010 使用 `codehead` 交互模式；当前 `-p` 不支持续聊，不适用于该场景。

真实仓库任务执行前，先用实际子进程检查解释器、独立的短 `TEMP` / `TMP` 路径和
pytest 的 `--basetemp`；Agent 自测与评测者验收都应使用已验证的短路径。
设置 `PYTEST_ADDOPTS` 时使用带引号的正斜杠绝对路径，并在 pytest 子进程中核对实际
basetemp 和 tmp_path 的父目录；仅确认预期目录可写不能发现参数解析后的路径变化。
用假 Provider 预检正常退出、跨进程恢复和恢复后的输入等待，不把预检计入真实模型样本。
每个命令只启动一个模型阶段，阶段结束后单独验收，再显式启动恢复；不要把多个任务
及其验收自动串行排队，以免停止当前验收时误中止下一任务。

`--allow-all-tools` 允许 shell 访问 workspace 之外；独立目录只是让任务数据分开，不构成进程隔离。真正的无人值守隔离应由执行环境提供。

答案、stderr、验收输出和结果记录都保存在 workspace 外。Codehead 默认产生的 `.codehead/` 运行数据不作为任务代码修改；若配置外部 `session_db`，应使用每次运行独有的绝对路径。忽略 `__pycache__/` 等解释器缓存，但不要忽略 Agent 新增的业务文件。

## 怎样判定完成

- **任务结果**：公开测试、评测者额外用例和修改范围均符合要求。001 使用事实核对，009 和 010 使用各自的场景规则。
- **验证行为**：单独记录 Agent 是否运行检查、是否根据失败修改、是否准确报告。最终代码正确但未验证，与最终代码错误，是不同结果。
- **Harness 状态**：单独记录正常结束、模型失败、步数耗尽、工具故障、中断或环境故障。进程退出码 0 不等于任务完成。

评测者在 Agent 结束后独立运行验收，不能只相信 Agent 的最终答案。公开测试只是起点；额外用例检查提示词已经公开的契约，不添加题目没有说明的新要求。不要求某个特定实现、工具顺序或函数写法。

007 需要另外评估新增测试是否能发现独立的错误变体。010 只有实际观察到 `ContextCompacted` 对应的成功压缩，才能评价「压缩后约束保留」；没有触发时记为「未触发」，不能记作成功或失败。

本任务集提供验收表和部分公开测试代码，没有实现自动验收器。额外用例需要评测者转成独立断言或人工核对。

## 最小结果记录

每题先跑一次用于发现初始化问题；之后若要比较两个版本，每题各用全新 workspace 重复至少三次，保留每次结果，不只挑最好的一次。重复次数是起步建议，不构成统计显著性的保证。

拿不到的指标写「未采集」。当前 print 模式的 usage 汇总来自正常模型请求的 `ModelCompleted`，不包含压缩摘要请求的 usage，不应直接当作整项任务的全部消耗。

失败可先按「理解错需求、定位错误、实现错误、没有验证、工具交互、权限处理、压缩后遗漏、运行环境」记录。不要仅凭一次失败就新增 Harness 机制；先看同类问题是否重复出现。
