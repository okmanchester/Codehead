## 结论

- Windows Shell 修复保留。确定性 A/B 探针复现旧版模块缺失和中文乱码，新版返回正确 SHA-256、中文 stdout/stderr 与非零退出码；真实模型任务是否调用 Get-FileHash 由模型自行决定。
- EOF 反馈不保留：010 的 A 组复读次数为 0、0、2，B 为 0、0、0，中位数均为 0，未满足预设的严格下降条件。总复读数降低及输入 token 中位数下降只作为观察，样本不足以确认收益。
- 004：A-2、A-4 在应用环境覆盖前验证文件值类型，违反先合并再校验；A-3 纠正错误测试后业务验收通过，但耗尽 20 步、未完成回合。B-2、B-3 通过；B-4 修正校验时留下非法文件值被接受的缺陷并耗尽步数。两组都出现模型实现/测试问题，不能把差异全部归因于 Harness。
- 008 两组均通过，B 的请求和输入 token 中位数没有降低。工具失败还包含 Bash 语法误用于 PowerShell、非 Git 目录执行 git、读取目录及错误的文本定位检查。004 的预期负向验证单独分类，不算 Harness 故障。本轮不增加规划或循环控制机制。

## 验证与口径

- 本地验证：组合候选为 407 项 pytest 通过、1 项跳过；撤回 EOF 后最终代码为 400 项通过、1 项平台测试跳过，Ruff lint、格式检查和 git diff --check 通过。保留的回归覆盖中文标准流/管道、cmdlet 与原生命令退出码及模块环境隔离。未在真实 Unix 主机运行。
- 独立验收运行公开/新增测试、业务额外用例和修改范围检查；部分 004 样本将原字段断言改成等价对象比较或局部变量，AST 文本检查误判，已逐一人工复核。原始判定和更正理由均留在归档，未改 Agent 产物。
- 尾部复读指同一资料文件再次返回的全部行号都已读取；只统计 notes/ 的成功读取。EOF 不代表被截断的长行内容完整。010 每次均自然触发 4 次压缩，已核对全部检查点中最初用户规则均移出活跃原文；没有补发早期规则。
- token 在 Provider 完整响应处单次统计，包含摘要及两份异常尝试的已知用量；缺失 usage 不估算。正常请求数用于总步骤比较，多回合的每回合步骤另存指标。
- 每组仅三次，且同时修改了 Shell 与 EOF；不能据此声称统计显著或把全部差异归因于单一改动。未计算货币费用。
