## 退出码问题与最小修复

先执行十项本地探针，再增加两个混合命令用例，发现了与一般“stderr 有内容”不同的
具体缺陷：原生命令成功之后，末条 Write-Error 的失败会被残留 LASTEXITCODE=0
掩盖，工具返回 0，而直接 PowerShell 返回 1。

修复只调整包装器的优先级：非零原生命令退出码优先返回，否则检查末条语句状态。
新增两项回归，修复前为 1 失败、1 通过，修复后通过；允许后续语句恢复成功的行为
保持不变。未改 Shell 选择、编码、超时、进程树、输出限制或工具接口。
这是对既有 cmdlet 失败保留契约的局部修复，不新增 ADR。

| 同一组退出码探针重放 | 12/12 通过 |

| 主工作区完整 pytest | 412 通过、1 跳过 |
| Ruff lint / 源码格式 / git diff --check | 通过 |

stderr 非空、非终止错误后成功和显式捕获错误都不应直接被判为失败；这与
[Windows PowerShell 5.1 的状态变量说明](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_automatic_variables?view=powershell-5.1)
及本地探针一致。未把工具改成遇错即停，也未在真实 Unix 主机运行。
