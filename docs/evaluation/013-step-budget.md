# 013：真实仓库任务的收尾预算诊断

只改变每回合步数上限，观察额外预算是否帮助完成最终交付。使用
[012](012-environment-resume.md) 的初始副本、首轮原始提示词与首轮验收，
不执行 Python 信息追加或恢复，不与此前运行合并统计。

## 固定设计

- 从 `2026-10-19-02.zip` 提取冻结 B 版驱动和相同的修改前 baseline；
  每次建立全新 workspace、会话和数据库，记录来源哈希和实际文件哈希。
- 顺序固定为 20、40、40、20 步，共四次；正常模型请求合计最多 120 次，
  摘要请求另计。异常保留并注明原因，不补跑、不追加样本。
- 固定 `deepseek-flash`、`https://api.deepseek.com`、thinking 关闭、输入预算
  65536、codehead 环境 Python 3.12.13，以及相同依赖和权限。
- 步数通过既有配置指定；不修改生产默认值、系统提示、工具行为、公共接口或存储格式。
- 一次命令只启动一个模型阶段；结束后独立验收，再显式启动下一次。
  使用上一轮相同的交互观察入口、600 秒期限和输入等待检查。

## 验收与解释

- 分开记录功能正确、检查通过、范围合规、终答准确和回合完成。
  完整成功要求以上均通过，不能只根据测试通过或进程退出码 0 判定。
- 模拟 Windows、Linux、Darwin，检查 OS/Shell 与执行入口一致及根目录
  AGENTS.md 的缺失、空白、非空、嵌套行为；平台模拟不等于真实 Unix 验证。
- 每次独立运行相关测试、完整 pytest、Ruff lint 和 src/tests 格式检查，
  人工复核已有测试、公共接口、其他提示文字、工具行为和修改范围。
- 记录请求数、含摘要的 token 用量、缺失 usage、耗时和终答步骤。
  审核首次自测通过后的动作，区分必要修复、补充验证和重复检查。
- 40 步样本若在第 20 步之后完整完成，只说明额外预算帮助了这些样本；
  四次诊断不证明稳定收益，不直接改变默认值，也不引入强制收尾机制。

原始脚本、事件、数据库及源码按本目录已有归档规则保留；报告与精简指标纳入版本管理。
