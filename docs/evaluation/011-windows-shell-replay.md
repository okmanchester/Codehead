# 011：Windows Shell 故障回放

真实仓库诊断任务，单次执行，不计入 001～008 的成功率。

## 初始副本

以本轮修改前的 Codehead 仓库为基础，不复制 `.git`、`.env`、运行数据或
`HANDOFF.md`。从 `2026-10-18-01.zip` 的 `source-a` 恢复
`src/codehead/tools/bash.py` 和 `tests/test_tools.py`，其余代码保持当前基线。
移除 ADR-0018 及其索引行、README 中直接描述该修复的段落，以及评测目录。
这是重建的故障副本，不是完整历史提交。执行前记录逐文件哈希和构造方式。

故障触发不能只依赖外层 Harness 继承的 `PSModulePath`：已修复的外层工具会先
清理它，导致 Agent 侧无法复现独立验收的模块故障。应提供只复现症状的诊断入口，
由评测夹具在待测 Python 进程内建立不兼容模块路径，再调用待测工具；入口不包含
修复逻辑，不修改驱动或被测生产源码来注入环境。下一次真实任务执行前，须同时
通过直接调用和冻结 Harness 工具调用验证旧实现失败、修复版正对照成功。
诊断入口及其构造说明一并归档，保持下述原始任务提示词不变。

## 给 Agent 的提示词

```text
修复这个仓库在 Windows 上执行 Shell 命令时的环境问题。实际观察到：从 Python 启动工具后，Get-FileHash 可能不可用；中文标准输出和错误信息出现乱码。
验收要求：中文路径文件的 SHA-256 正确；中文 stdout、stderr 和向 Python 原生命令传递的管道文本正确；成功返回 0，cmdlet 失败和原生命令指定的非零退出码保持正确；执行前后父进程环境不变，API key 仍不得传给 Shell 子进程。
保持现有 Shell 选择、超时、输出限制、取消和进程树清理行为，不增加外部依赖。请自行定位原因、修复、补充回归测试并同步必要的行为说明。不要削弱或删除已有测试。执行相关检查并如实说明结果。
```
