# 开发任务收尾

目标是让任务完成后只留下需要交付或长期维护的文件。此 skill 可自动选择，
`AGENTS.md` 要求在开发任务结束时执行；也可用 `$task-cleanup` 单独调用。

## 检查与判定

- 结合任务开始时记录的 Git 状态、执行过的命令和当前差异，辨认本任务产物。
  检查已跟踪、未跟踪和相关的忽略文件；已提交文件也要纳入价值审查。
  若缺少起始状态，不凭修改时间或文件名认定文件由本任务产生。
- 先查看 `git status --short`、`git diff --stat` 和相关文件列表，再检查实际产生
  日志、测试副本、缓存或报告的目录。全仓体积扫描用于明确的仓库审查或发现异常时，
  普通任务只检查相关目录，避免为收尾重复扫描所有历史归档。
- 核对候选文件的用途、调用方与文档引用。任务规范、必要回归测试和固定配置可能仍有
  长期价值；一次性脚本、原始输出和重复快照需要具体判断。体积大小或被忽略均不代表可删除。
- 不读取或修改 `HANDOFF.md`，除非用户明确要求交接；不为了收尾创建计划、总结、
  清理报告或额外归档文件。

## 清理边界

- 可自动删除：确认由本任务产生、没有运行中任务占用，且不含唯一证据的可重建临时产物。
  若目录混有历史文件，只处理已确认属于本任务的部分。
- 历史已跟踪文件、历史忽略文件及用途不明文件：列出路径、用途、删除理由和影响，
  用户确认后再删。用户已明确授权的清理清单直接执行，无需重复确认。
- 不自动清除会话数据库、凭据、环境配置、虚拟环境、唯一评测证据或 Git 内部文件。
  不为满足目录整洁而删除失败现场；先确认其排查价值。以重复为由删除时核对内容哈希，
  保留当前配置引用的副本；唯一产物不能仅因可重跑模型或外部服务而视为可重建。
- Windows 递归删除前，解析并核对绝对目标位于本仓库，检查目录链接不会指向边界外，
  用同一 PowerShell 中的 `Remove-Item -LiteralPath` 执行。占用或权限问题只报告具体残留，
  不终止其他任务或扩大删除范围。

## SWE-bench 收尾

本任务运行过 SWE-bench 时，复核驱动按项目保留策略执行的自动清理及其残留警告。
可运行 `python -m scripts.swebench cleanup` 预览已完成产物；手动执行 `--apply` 时，
仅处理本任务或用户已授权的历史产物，通用的历史文件确认边界不变。
确认补丁、预测、轨迹、会话、费用、终态、attempt 标记及官方评分证据仍在；
基础设施或验收失败保留的现场，不作为普通缓存删除。具体保留规则和命令见
[README](../../../README.md#评测产物保留与清理)。

## 规则维护与复查

- 需要在本地保留的生成物使用有明确范围的忽略规则；不要笼统忽略业务文件或整个文档目录。
  `.gitignore` 不会解除已有跟踪，清理已跟踪文件时要核对最终差异中的删除记录。
- 文件移除后同步清理失效引用、过时的保留要求和空目录。已有提交中的文件通过新的删除
  变更撤销保留决定，不重写历史，不自动提交或推送，也不改动用户已有变更。
- 清理完成后复查 Git 状态、实际文件与相关引用，运行 `git diff --check`。
  若删除涉及行为，运行必要的相关验证；已有检查通过后，不为纯清理重复完整测试。
  新检查产生的本任务临时文件也在最终答复前处理，不能删除验证仍需使用的文件。
- 最终答复简述删除内容和实际验证结果；未确认的历史候选与残留单独说明。
  仅在实际测量时报告释放空间；没有候选时一句话说明即可，不写过程文档。
